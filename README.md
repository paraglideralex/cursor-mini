# Локальный RAG-ассистент по репозиторию

Локальный ассистент для работы с кодовой базой на основе RAG (Retrieval-Augmented Generation). Работает полностью офлайн, без облачных API и сетевых запросов.

## Возможности

- **Полная локальность**: все модели и данные локальные, никаких сетевых запросов
- **RAG архитектура**: семантический поиск по коду + генерация ответов
- **Инкрементальная индексация**: быстрое обновление индекса при изменениях
- **Интерактивный REPL**: удобный интерфейс командной строки
- **Мультиязычность**: поддержка русских вопросов и кода на разных языках
- **Цитирование источников**: все ответы содержат ссылки на фрагменты кода
- **Прогресс-бары**: визуальный прогресс для индексации и генерации ответов
- **Таймеры**: отображение времени выполнения операций

## Требования

### Система
- **ОС**: Windows 11
- **Python**: **3.11.x** (обязательно!)
- **RAM**: 16 GB+ (рекомендуется 32 GB)
- **CPU**: Многоядерный процессор (протестировано на i7-13700H)

### Модели

Перед использованием необходимо вручную скачать:

1. **LLM модель**: Qwen2.5-Coder 7B Instruct (GGUF формат, q4_k_m квантизация)
   - Скачать: https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct-GGUF
   - Файл: `qwen2.5-coder-7b-instruct-q4_k_m.gguf`
   - Размер: ~4.3 GB

2. **Embeddings модель**: Мультиязычная модель (рекомендуется multilingual-e5-large)
   - Скачать: https://huggingface.co/intfloat/multilingual-e5-large
   - Папка со всеми файлами модели
   - Размер: ~2.2 GB
   
**Важно**: Модели можно скачать **вручную через браузер** или через `huggingface-cli`. Оба способа равнозначны!

## Установка

### 1. Создание виртуального окружения

**ВАЖНО**: Используйте Python 3.11!

```bash
# Проверка версии Python
python --version  # должно быть 3.11.x

# Создание venv
python -m venv venv

# Активация
venv\Scripts\activate
```

### 2. Установка зависимостей

```bash
cd local_repo_assistant
pip install -r requirements.txt
```

**Примечание**: Установка `llama-cpp-python` может занять время. Для CPU-only версии дополнительных действий не требуется.

### 3. Размещение моделей

Создайте структуру папок:

```
cursor-mini/  (или ваша корневая папка проекта)
  models/
    embeddings/
      multilingual-e5-large/
        config.json
        model.safetensors
        tokenizer.json
        ...
  qwen2.5-coder-7b-instruct-q4_k_m.gguf
  local_repo_assistant/
    ...
```

#### Способ 1: Через huggingface-cli (требует доступ к HuggingFace)

```bash
# Из корня проекта
pip install huggingface-hub

# Скачать embeddings
huggingface-cli download intfloat/multilingual-e5-large --local-dir models/embeddings/multilingual-e5-large --local-dir-use-symlinks False
```

#### Способ 2: Ручное скачивание (работает без доступа к HuggingFace CLI)

1. Перейдите на https://huggingface.co/intfloat/multilingual-e5-large
2. Нажмите "Files and versions"
3. Скачайте **ВСЕ файлы** (можно по одному через браузер):
   - `config.json`
   - `model.safetensors` (основной файл, ~2.2 GB)
   - `tokenizer.json`
   - `tokenizer_config.json`
   - `special_tokens_map.json`
   - `sentencepiece.bpe.model`
   - Остальные файлы (если есть)
4. Положите все файлы в `models/embeddings/multilingual-e5-large/`

**Важно**: Убедитесь что все файлы лежат в одной папке `multilingual-e5-large/`!

LLM модель (`.gguf` файл) можно просто скачать и положить в корень проекта.

### 4. Создание конфигурации

Скопируйте пример конфигурации:

```bash
copy .assistant\config.json.example .assistant\config.json
```

Отредактируйте `.assistant/config.json`:

```json
{
  "repo_root": "C:/путь/к/вашему/репозиторию",
  "storage_dir": ".assistant/storage",
  
  "llm_model_path": "models/llm/qwen2.5-coder-7b-instruct-q4_k_m.gguf",
  "embedding_model_dir": "models/embeddings/multilingual-e5-large",
  
  "include_extensions": [
    ".cs", ".py", ".js", ".ts", ".java", ".cpp", ".h", ".go"
  ],
  
  "exclude_dirs": [
    "bin", "obj", "node_modules", ".git", ".vs", "packages", "dist", "venv"
  ],
  
  "max_file_size_kb": 500,
  
  "chunk_size_lines": 250,
  "chunk_overlap_lines": 30,
  
  "top_k": 12,
  "max_context_chars": 60000,
  
  "llm_ctx_size": 8192,
  "llm_max_new_tokens": 700,
  "llm_temperature": 0.2,
  "llm_seed": 42
}
```

### 5. Запуск

```bash
python app\main.py
```

## Настройка параметров

### Параметры индексации

- **`chunk_size_lines`**: Размер чанка в строках (по умолчанию: 250)
- **`chunk_overlap_lines`**: Перекрытие между чанками (по умолчанию: 30)
- **`include_extensions`**: Расширения файлов для индексации
- **`exclude_dirs`**: Директории для исключения

### Параметры RAG

- **`top_k`**: Количество релевантных фрагментов для контекста (по умолчанию: 12)
- **`max_context_chars`**: Максимальный размер контекста в символах (по умолчанию: 60000)

### Параметры LLM

- **`llm_ctx_size`**: Размер контекстного окна модели (по умолчанию: 8192)
- **`llm_max_new_tokens`**: Максимальная длина ответа в токенах (по умолчанию: 700)
- **`llm_temperature`**: Температура генерации, 0.0-1.0 (по умолчанию: 0.2)
- **`llm_seed`**: Seed для воспроизводимости результатов (по умолчанию: 42)

### Параметры GPU (опционально)

- **`use_gpu`**: Использовать GPU (по умолчанию: false)
- **`gpu_layers`**: Количество слоёв модели на GPU (по умолчанию: 0)
  - `0` = CPU-only
  - `32` = часть слоёв на GPU (быстрее)
  - `-1` = все слои на GPU (максимальная скорость)

**Для включения GPU:**
```json
{
  "use_gpu": true,
  "gpu_layers": 32
}
```

**Требования для GPU:**
- NVIDIA GPU с поддержкой CUDA
- Установить `llama-cpp-python` с CUDA: `pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu121`
- Для embeddings нужен PyTorch с CUDA: `pip install torch --index-url https://download.pytorch.org/whl/cu121`

## Безопасность и локальность

Система строго соблюдает требования локальности:

1. **Offline режим**: При старте устанавливаются переменные окружения:
   - `TRANSFORMERS_OFFLINE=1`
   - `HF_HUB_OFFLINE=1`

2. **Запрет сетевых запросов**: Никакие компоненты не могут делать сетевые запросы в рантайме

3. **Локальные модели**: Все модели загружаются только из локальных файлов

4. **Конфиденциальность**: Код не выходит за пределы локальной машины

## Структура хранилища

Все данные хранятся в `.assistant/storage/`:

```
.assistant/
  config.json          # Конфигурация
  storage/
    docstore/
      chunks.json      # Тексты чанков и метаданные
    vectorstore/
      hnsw_index.bin   # Векторный индекс
      id_mapping.pkl   # Маппинг ID
    meta/
      indexing_meta.json  # Метаданные индексации
```

## Решение проблем

### Ошибка: "Файл модели LLM не найден"
- Проверьте путь `llm_model_path` в конфиге
- Убедитесь, что файл `.gguf` существует по указанному пути

### Ошибка: "Директория embeddings модели не найдена"
- Проверьте путь `embedding_model_dir` в конфиге
- Убедитесь, что папка содержит все файлы модели (config.json, model.safetensors, и т.д.)

### Медленная индексация
- Уменьшите `chunk_size_lines` (например, до 150)
- Добавьте больше директорий в `exclude_dirs`
- Увеличьте `max_file_size_kb` чтобы исключить большие файлы

### Медленная генерация ответов
- Уменьшите `llm_max_new_tokens` (например, до 500)
- Уменьшите `top_k` (например, до 8)
- Уменьшите `max_context_chars` (например, до 40000)

### Нерелевантные результаты
- Увеличьте `top_k` (например, до 15-20)
- Проверьте, что файлы правильно проиндексированы командой `status`
- Переформулируйте вопрос более конкретно

## Производительность

Типичные показатели на i7-13700H, 32 GB RAM (CPU-only):

- **Индексация**: ~50-100 файлов/мин (зависит от размера файлов)
- **Embeddings**: ~10-15 чанков/сек
- **Поиск**: < 1 сек
- **Генерация ответа**: 10-20 сек (зависит от длины)

## Ограничения

1. **Только CPU**: Для GPU потребуется дополнительная настройка llama-cpp-python
2. **Размер контекста**: Ограничен `llm_ctx_size` (8192 токена)
3. **Языки кода**: Лучше всего работает с популярными языками (C#, Python, JS, Java)
4. **Текстовые файлы**: Работает только с текстовыми файлами
